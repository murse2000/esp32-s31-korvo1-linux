# CPU·메모리 최적화와 검증 (2026-11-19)

## 최종 선택

추가 캐시와 명령 묶기는 구현했지만, 반복 측정에서 일반 스크롤·슬라이더의 CPU 감소가 일관되게 나타나지 않았습니다. 기본 `korvo-ui`는 기존 PPA/2D-DMA 그리기를 유지하고, 추가 경로는 별도 `korvo-ui-extra`에 제공합니다. 기본 실행 파일에는 추가 렌더러 코드를 링크하지 않습니다.

두 실행 파일 모두 800×480, 약 18MHz LCD, 33ms refresh 설정을 유지합니다. 다음 수정은 기본 모드에도 적용합니다.

- 작업이 없는 가속 unit이 `LV_DRAW_UNIT_IDLE`을 반환하도록 수정.
- 작은 내용 변경과 이동 잔상만 다시 그리는 스크롤 갱신.
- 스크롤 안전성 검사를 refresh당 한 번으로 병합.
- 사용하지 않는 코드 제거, 카메라 버퍼 지연 할당.
- 데모 음악을 빌드 호스트에서 생성하여 microSD에 설치.
- 음악 플레이어의 고정 5ms polling을 LVGL timer 기준으로 변경.

초기의 추가 10~30%는 측정 전 목표였습니다. **일반 드래그에서 그 수준의 추가 감소를 확인했다고 주장하지 않습니다.** 앞선 `023a194e → 20cf441d` 단계의 52%/49% 수치와도 합산하지 않습니다.

## CPU를 소모하던 무한 대기

LVGL dispatch 반환값 0은 작업 중, `LV_DRAW_UNIT_IDLE`은 작업 없음입니다. 기존 PPA 포트는 할 일이 없을 때 0을 반환하여 `lv_canvas_finish_layer()`의 dispatch 요청 대기가 끝나지 않을 수 있었습니다. Buffered vector 데모가 화면 초기화 도중 CPU를 계속 사용하며 멈추는 것을 보드에서 재현했습니다.

기본·확장 렌더러 모두 반환값을 고쳤습니다. 회귀 장면은 ARGB8888 canvas에 사각형을 그리고 finish가 반환되는지와 중심 픽셀을 검사합니다. 벡터 데모를 포함한 12종의 실행·종료도 확인합니다. 벡터의 모든 계산을 하드웨어로 가속했다는 뜻은 아닙니다.

## 기본 모드 비교

같은 Linux 7.3.4 `#11`, PPA 드라이버, LVGL 9.2.2에서 이전 포트 `20cf441d`와 최종 기본 포트를 비교했습니다. UART에서 실행하고 SSH는 종료했습니다. 성능 오버레이·추가 profiler는 끄고 같은 검사 코드로 90개 위치를 33,333µs 간격으로 요청했습니다. 실제 값 변경은 89회입니다. CPU는 `getrusage`의 user+system 합입니다.

단위는 µs입니다. [원본 출력](cpu-2026-11-19.txt)을 제공합니다.

| 동작 | 회차 | 이전 CPU | 기본 CPU | 이전 wall | 기본 wall |
|---|---:|---:|---:|---:|---:|
| slider | 1 | 362718 | 325444 | 3009033 | 3009186 |
| slider | 2 | 301302 | 326730 | 3006269 | 3008214 |
| slider | 3 | 306666 | 333888 | 3004331 | 3009431 |
| scroll | 1 | 1372711 | 1533676 | 3000700 | 3778624 |
| scroll | 2 | 1398360 | 1436168 | 3264925 | 3007940 |
| scroll | 3 | 1461686 | 1423662 | 3115769 | 3008815 |

중앙값은 slider 306666 → 326730µs, scroll 1398360 → 1436168µs로, 이 표는 추가 CPU 감소를 입증하지 않습니다. 캐시와 page fault에 따른 변동도 큽니다. 이전 slider 1회차·scroll 1/3회차, 수정 scroll 1회차에는 major page fault가 있었습니다. 기본 포트는 기존의 잘린 mask/동기 전송을 유지하면서 정확한 IDLE 상태와 부분 변경 처리를 적용합니다.

CPU가 늘어나는 설정을 무조건 적용하지 않기 위해 [기준값 조정](cpu-tuning-2026-11-19.txt)과 [확장 경로의 5회 비교](cpu-extra-five-2026-11-19.txt)도 수행했습니다. 넓이가 계속 바뀌는 bar/slider는 전체 모양 캐시의 miss·생성 비용 때문에 기존 잘린 mask 경로로 유지합니다. 초기의 짧은 측정에서 보였던 개선율을 최종 보장 수치로 사용하지 않습니다.

## 추가 경로

`korvo-ui-extra`, `lvgl-music-demo-extra`는 글자/폰트 심벌·곡선 mask 캐시, 그림자 모서리 3개 재사용, 최대 16개 명령 묶기, immutable A8 source 재사용을 제공합니다. 기존 scratch 32KiB와 예약 canvas의 빈 공간을 사용합니다. 명령 사이에 SW 그리기가 필요하거나 task가 하나씩 생성되면 단일 ioctl로 처리합니다.

```sh
/etc/init.d/S97lvgl-music-demo stop
korvo-ui-extra widgets
# 종료 후 기본 메뉴로 복귀
/etc/init.d/S97lvgl-music-demo restart
```

`KORVO_CACHE_DISABLE=1`, `KORVO_BATCH_DISABLE=1`은 확장 실행 파일의 비교 옵션입니다. `KORVO_PPA_CPU_FILL_LIMIT=4096`은 확장 포트의 CPU/PPA fill 기준을 바꿉니다. 기본값은 65536입니다. `KORVO_UI_STATS=1`로 hit/miss, 명령 수, `dirty_reused`를 확인할 수 있습니다.

## 정확도·기능 검사

- 스크롤 11개 장면: 세로/가로, 넓은/작은 내용 변경, 입력 병합, 투명 컨테이너, Tabview, 사용자 그리기, floating 자식, overlay/gradient fallback. 전체 384,000픽셀을 무오차 비교하며 작은 변경은 실제 `dirty_reused`도 검사합니다.
- 확장 포트의 CPU/PPA fill 기준 비교: 90단계 캡처가 일치하고 PPA fill 명령 수가 늘어야 통과합니다.
- 원본 SW·기본·확장·cache 비활성·batch 비활성 경로 비교. 기본/확장/cache/batch 변형은 정확히 일치해야 합니다. SW/PPA는 지정된 반투명 영역만 RGB565 채널당 한 단계 차이를 허용하고 텍스트는 정확히 일치해야 합니다.
- ARGB canvas 완료·픽셀 검사와 그림자 반지름별 cache hit 검사.
- copy/strided crop/좁은 사각형 cache 보존/홀수·짝수 framebuffer reuse/5색 fill/RGB565·ARGB8888·A8/immutable A8/bounds/batch 순서·부분 완료·count bounds 검사.
- Goodix widgets 드래그, 메뉴·HOME 전환, 카메라 프레임, ALSA 재생.

최종 기본 모드에서 11개 스크롤 장면이 전부 통과했고 작은 변경의 `dirty_reused=1`도 확인했습니다. 확장 포트의 fill 비교와 모든 렌더링 모드의 픽셀 비교도 통과했습니다. 재부팅 후 기본 메뉴·Wi-Fi 자동접속, 12개 데모 실행/종료, 카메라 영상, 1초 ALSA 재생을 확인했습니다. 기본·확장 모드 각각 widgets/HOME와 audio/HOME/camera/HOME도 통과했습니다. 설치 파일과 Buildroot target의 SHA-256이 일치했고 PPA 오류는 0건이었습니다.

픽셀 캡처·파일 비교·SSH가 포함된 실행 시간은 CPU 표와 섞지 않습니다. [widgets 원본](widgets-2026-11-19.txt)은 입력 처리·관성 이동에 따라 scroll 호출 수가 달라 정량적인 동일 작업 비교로 사용하지 않습니다.

## 메모리와 오디오

함수/데이터 section 제거로 사용하지 않는 코드를 제외했습니다. 카메라의 115,200바이트 정적 배열은 카메라 화면에서만 할당·초기화하고 종료 시 해제합니다. 파일 크기·BSS·실제 resident RAM은 서로 다른 값입니다.

14초 stereo 22050Hz/16-bit WAV(1,234,844바이트)는 빌드 호스트에서 생성하여 `/usr/share/sounds/korvo-lvgl-demo.wav`에 설치합니다. 첫 재생 때 보드에서 수행하던 약 90만 회의 sine 계산·sample 생성과 `/tmp`의 약 1.18MiB 파일을 제거했습니다. ALSA/driver의 재생 비용까지 없어지는 것은 아닙니다. target Python은 필요하지 않습니다.
